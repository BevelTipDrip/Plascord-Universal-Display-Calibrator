## What it does

`research/tools/changemap.py` reads every card under `research/changes/<area>/`, recomputes facts from git and the
code into `_facts/` (commits since `base_ref`, switch names found by `switch_patterns`, doc headings and anchors,
test write-ups), answers lookups (`file`, `switch`, `commit`, `test`, `find`, `doc`, `show`, `area`), writes
`INDEX.md` / `TESTS.md`, and `check` validates it all. The `docs-check` workflow runs `check` on every push and pull
request. `branches` fetches the remote, reads each unmerged branch's `research/branches/<branch>.md` from that
branch, and compares its changed and planned files, areas and interfaces with the current branch's, plus a trial
merge (`git merge-tree`); `new-branch` writes a reference file from `research/templates/branch.md`. `queue` reads the work queue's tables
(`plan-work-queue.md`, `plan-work-queue-done.md`), prints Now and Next or one item with every reference to it, and
`check` validates the rows and every `work_queue:` / `queue:` reference.

## Invariants

- Standard library only, Python 3.8+: every person and CI must run it with no install.
- `INDEX.md` and `TESTS.md` depend only on the cards and the docs, never on local git state (branches, remotes), so
  the file `index` writes is the same on every machine and `check` can compare against it.
- `_facts/` is regenerated by `check` and by lookups when missing; it is not committed (`.gitignore`).
- Card front matter stays `key: value` with comma-separated lists (`LIST_KEYS`); a new list key must be added there.
- A card's `commits:` must stay reachable: merge commits only (repo-boundaries.md).
- A branch's reference file is found only at `research/branches/<exact branch name>.md` on that branch; `branches`
  reads nothing from `main` for other branches, so a branch that is not pushed is invisible to others.
- The queue's tables are found by an `ID` column; rows are one line each (`split_row` keeps `|` inside backticks).
  Columns are read by header name, so renaming `State`, `Owner`, `Branch`, `Kind`, `Result` or `Commit / PR`
  breaks the checks.
- `branches` only reads and fetches: it never changes a branch, the working tree or the remote.
- In GitHub Actions the branch under check comes from `GITHUB_HEAD_REF` (pull requests) or `GITHUB_REF_NAME`
  (pushes), since the checkout is detached.

## Interactions

- `changemap.config.json` sets areas, code paths, switch patterns, default columns and test-ID patterns; a change
  there can turn many cards' checks on or off at once.
- `research/templates/card.md` is the form `new` copies; keep its keys in step with `LIST_KEYS` and `REQUIRED`.

## Evidence

- Generalized from a single-repo tool used on a long-running project (about 200 cards, every code commit and switch
  covered). Run on this project at setup, 2026-11-18 (`check`: 0 errors).

## History and pitfalls

- The original tool printed a branch column in the index from local branches: the index then differed per machine.
  Dropped here for a deterministic index.
- Squash and rebase merges rewrite hashes and orphan the cards' `commits:`; `check` names this in its error.
